  3. TogetherBefore testers

    Four layers, the way most app companies do it. The log of everything people do is the source of truth, and memory and summaries are rebuilt from it, so backing up the database covers all of it.

    • Daily backups in Supabase (have it now): your Pro plan takes one every day and keeps 7. Check them under Database → Backups
    • A nightly copy somewhere else (I build it, before testers): a scheduled job copies the whole database each night, encrypts it, and stores it outside Supabase, in a private storage bucket you open (Cloudflare R2 or Backblaze B2, about 10 minutes, free or close to it at this size). It keeps 7 nightly, 4 weekly and 3 monthly copies, so nothing is older than about 90 days. Your GitHub repository is public, so the copy never touches GitHub itself; only the job runs there, and it never prints any data
    • Rewind to any minute (turn on before you charge): Supabase’s Point-in-Time Recovery add-on, so a bad update at 2:14 p.m. can be undone to 2:13. It’s priced by how many days it keeps; 7 days is the usual start
    • A restore drill: every 3 months, and before any big database change, restore a copy into a spare project and check it works. A backup nobody has restored is only a hope
    • Privacy: backups are encrypted, only you can open them, and the privacy page says deleted data leaves backups within 90 days
